# Банк задач и приложение подготовки «Саня дай сотку»

Документ для Claude Code. Лежит в корне репозитория.
Читать первым перед любой работой над проектом.

---

## 1. Что строим

Telegram Mini App для подготовки к ЕГЭ и ОГЭ по физике:

- **банк задач** с фильтрами, формулами и чертежами;
- **личный кабинет ученика** — прогресс по темам, домашние задания, автопроверка ответов;
- **админка преподавателя** — назначить ДЗ, посмотреть, кто что решил, где проваливается.

Автор и единственный преподаватель — Александр. Учеников порядка 15–25, плюс группы.
Проект личный, не коммерческий продукт: цель — убрать ручную работу по выдаче и проверке задач.

### Почему Telegram Mini App, а не сайт

Mini App — это обычная веб-страница, открытая во встроенном браузере Телеграма.
Та же страница работает и как сайт. Но Телеграм даёт **готовую авторизацию**:
передаёт приложению подписанные данные пользователя (`initData`), подпись
проверяется токеном бота на сервере. Нет регистрации, паролей, восстановления доступа.

Решение принято: строим одну веб-страницу, которая работает и как сайт, и как Mini App.
Отдельного мобильного приложения не делаем.

## 2. Принципы, от которых не отступаем

**Данные отдельно от приложения.** Банк задач — это файлы в репозитории,
а не записи в базе приложения. Приложение их только читает. Так банк переживёт
любую переделку интерфейса и остаётся полезным сам по себе.

**Каждый этап выпускается и приносит пользу.** Не строим ЛК раньше банка.
После каждого этапа есть работающая вещь, которой можно пользоваться.
Если проект встанет на четвёртом этапе, первые три всё равно работают.

**Минимум персональных данных.** Храним только Telegram id, имя и прогресс.
Ни телефонов, ни email, ни адресов. Ученики — несовершеннолетние,
лишние данные о них собирать нельзя.

**Автопроверка — ядро ценности.** В банке у каждой задачи есть ответ.
Значит ученик вводит ответ, система сверяет сама. Это то, что убирает
ручную проверку и делает ЛК осмысленным. Всё остальное — обвязка вокруг этого.

**Пополнять банк должно быть быстро.** Добавить задачу — меньше трёх минут.
Если дольше, банк не будет расти, и приложение останется пустым.

## 3. Формат данных банка

Одна задача — один файл `bank/<раздел>/<id>.md`. Markdown с YAML-шапкой.
Не один большой JSON: его нельзя пополнять по одной задаче.

```yaml
---
id: elem_coulomb_v1_n11      # из \label{task:...} в исходном .tex, уникален
exam: ЕГЭ                    # ЕГЭ | ОГЭ | оба
kim: 11                      # номер задания в КИМ
section: Электродинамика
theme: ЗАКОН КУЛОНА. НАПРЯЖЁННОСТЬ ЭЛЕКТРИЧЕСКОГО ПОЛЯ
topic: 3.1.1                 # код темы курса — главное поле для фильтров
level: Б                     # Б | П | В
type: расчётная              # расчётная | соответствие/выбор | качественная | расчётная (часть 2)
variant: 1
answer: "9"
has_image: false
author_task: false           # true, если \kimavt — авторская, а не типаж ФИПИ
tags: [ЭЛЕКТРОДИНАМИКА, КУЛОН]
source: col.tex
---

## Условие

Текст с формулами в долларах: $F = k\dfrac{q_1 q_2}{r^2}$.

## Рисунок (TikZ)

```latex
\begin{tikzpicture} ... \end{tikzpicture}
```

## Решение

Текст решения. Может отсутствовать — тогда TODO.
```

### Поле `topic` — ключевое

Код темы (`1.1.1`, `3.2.4`, `4.6`) — та же нумерация, что в курсах ЕГЭ.
На ней держатся фильтры, прогресс ученика и связь с материалами курса.
В исходных .tex этого поля нет, есть только словесная тема заглавными буквами.
Нужна таблица соответствия `themes.csv`: словесная тема → код. Парсер по ней проставит коды всем задачам.

### Формулы и чертежи

Формулы остаются LaTeX в долларах, рисует их **KaTeX в браузере**.
Ничего не предкомпилируем: текст остаётся текстом и ищется поиском.

Чертежи — TikZ. Компилируются в **SVG один раз при сборке** скриптом
(`pdflatex` + `pdf2svg` или `dvisvgm`), результат кладётся в `assets/`.
В браузере показывается готовый SVG.

### Что требует ручной работы

Задачи с `type: соответствие/выбор` (КИМ 6, 16, 18, 20) содержат таблицы
с графиками в клетках. Парсер их вытаскивает, но вёрстку для веба надо
собирать руками как HTML-таблицу. Таких задач немного, видно по полю `type`.

## 4. Этапы

### Этап 0 — Данные. СЕЙЧАС

Парсер уже написан и проверен: из трёх файлов библиотеки извлёк 36 задач,
все с ответами, метаданные заполнились автоматически кроме `topic`.

- [ ] прогнать парсер по всем 15–20 файлам библиотеки
- [ ] составить `themes.csv` (словесная тема → код темы)
- [ ] парсер проставляет `topic` по этой таблице
- [ ] скрипт сборки: папка с .md → `bank.json`
- [ ] скрипт компиляции TikZ → SVG
- [ ] глазами проверить задачи, где парсер не справился

Результат: 200–250 задач в едином формате. Это главный актив проекта.

### Этап 1 — Банк задач. Статика, без аккаунтов

Одна HTML-страница. Фильтры: экзамен, раздел, тема, номер КИМ, уровень, тип.
Показ условия и чертежа, ответ и решение раскрываются по кнопке.
Поиск по тексту. Выкладывается на GitHub Pages (бесплатно, с HTTPS).

Результат: ты сам пользуешься на уроках, ученики заходят по ссылке.
Полезно уже на этом шаге, аккаунты не нужны.

### Этап 2 — Telegram Mini App

Бот, кнопка «Открыть банк задач», та же страница внутри Телеграма.
Проверка `initData` на бэкенде — появляется понятие «кто зашёл».
База ещё не нужна.

Результат: заходить удобнее, ученик уже узнан по имени.

### Этап 3 — ЛК: прогресс

Появляется база данных. Таблицы: `users`, `attempts` (кто, какая задача, ответ, верно ли, когда).

Ученик решает задачу, вводит ответ, система сверяет с полем `answer` —
**автопроверка**. Видит свой процент по каждой теме.

Результат: ученик видит движение, ты перестаёшь спрашивать «решил?».

### Этап 4 — ЛК: домашние задания

Ты собираешь подборку задач (фильтрами или вручную), назначаешь ученику,
ставишь срок. Ученик видит ДЗ в кабинете, решает, вводит ответы.
Бот напоминает о сроке.

Результат: главная ценность проекта. Выдача и проверка ДЗ перестают
быть ручной работой, таблица учёта становится не нужна.

### Этап 5 — Админка

Список учеников, у кого что не сделано, где кто проваливается по темам.
Заменяет лист «Проблемные темы» в таблице статистики.

### Этап 6 — Пробники

Генерация варианта из банка по структуре КИМ, на время, с бланком ответов.
Результат — в прогресс ученика.

## 5. Технологии

Решения, которые не пересматриваем без причины:

| Что | Чем | Почему |
|---|---|---|
| Банк | Markdown + YAML в git | пополняется по одному файлу, переживает переделки интерфейса |
| Формулы | KaTeX | быстрее MathJax, достаточно для школьной физики |
| Чертежи | TikZ → SVG при сборке | TikZ уже написан, переделывать нечего |
| Фронтенд | ванильный JS или минимальный фреймворк | страница простая, тяжёлый стек тут не нужен |
| Хостинг этапа 1 | GitHub Pages | бесплатно, HTTPS из коробки, Телеграму HTTPS обязателен |
| Авторизация | Telegram initData | бесплатно, без паролей и регистрации |
| База с этапа 3 | Postgres (Supabase или аналог) | бесплатного тарифа хватает на 25 учеников с запасом |

Палитра бренда: синий `#0066FF`, тёмный `#1B1F3B`, оранжевый `#FF6B35`.
Шрифты: Oswald для заголовков, PT Sans для текста.

## 6. Чего не делаем

**Не пишем своё приложение для iOS и Android.** Mini App закрывает обе платформы.

**Не делаем регистрацию по email и паролю.** Авторизация только через Телеграм.

**Не храним решения в базе.** Решения — часть банка, то есть файлы в репозитории.
В базе только попытки учеников.

**Не начинаем с ЛК.** Этапы 3–4 имеют смысл только когда в банке есть объём.
ЛК поверх пустого банка — это аккаунты, в которых нечего делать.

**Не переносим в банк задачи из лекций.** Там часть задач придумана ИИ
и условия редуцированы. Источник — только библиотека ЕГЭ.

## 7. Известные проблемы в исходных файлах

Найдено при разборе библиотеки, исправить на стороне .tex:

- В `energy.tex` используется окружение `stylebasic`, которого нет в `egephys-style.sty`.
  Файл в таком виде не компилируется — проверить, не потерялась ли более свежая версия стиля.
- Нумерация «Задача N» перезапускается в каждой пачке, в одном файле есть две «ЗАДАЧА 2».
  На парсер не влияет (опирается на `\label`), но глазами путает.
- Уровни `taskmedium` и `taskadvanced` в разобранных файлах не встречались — все задачи `Б`.
  Если в остальных файлах они есть, парсер подхватит автоматически.
